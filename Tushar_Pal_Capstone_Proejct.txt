PROJECT PURPOSE
Classify news headlines and optional descriptions as positive, neutral or
negative using a trained TF-IDF + logistic regression pipeline. Includes
single/batch inference, evaluation, drift checks, explanations, Docker,
GitHub Actions, Prometheus and Grafana.

This is news sentiment classification, not stock-price prediction.
Company-specific event detection is not implemented. Labels in the supplied
dataset are automated/weak labels; test results are not human-verified accuracy.
The API uses Python's standard-library HTTP server, not FastAPI.

11. PROMETHEUS AND GRAFANA
======================================================================
Check Prometheus Targets: job news-sentiment must be UP.
Generate predictions and confirm counters change.

Queries:

up{job="news-sentiment"}
sum(news_requests_total)
sum(news_predictions_total)
sum(news_server_errors_total)
sum(news_client_errors_total)
60 * sum(rate(news_requests_total[5m]))
sum by (label) (news_predictions_by_label_total)
1000 * sum(rate(news_request_duration_seconds_sum[5m])) / sum(rate(news_request_duration_seconds_count[5m]))
histogram_quantile(0.95, sum by (le) (rate(news_post_latency_seconds_bucket[5m])))

The last query returns seconds; multiply by 1000 for milliseconds.
New error/histogram metrics require the updated app to be running.
Latency covers all POST operations, not prediction requests alone.
Counters reset when the API process restarts. Rates require multiple scrapes.
Idle latency/error-rate ratios may be blank. These metrics do not measure
sentiment accuracy. Existing Grafana panels still show their original scope.
